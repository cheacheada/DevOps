# 4주차: 리눅스 네트워크

## 핵심 개념
IP는 컴퓨터의 주소이고 포트는 그 컴퓨터의 서비스 입구다. DNS는 도메인을 IP로 해석한다. `127.0.0.1`은 자기 컴퓨터를 가리킨다. 서버가 `0.0.0.0`에 바인딩되면 모든 IPv4 인터페이스에서 연결을 받을 수 있지만 실제 외부 접근 여부는 방화벽과 네트워크 설정에도 영향을 받는다.

## 실습 명령
```bash
ip addr
ss -lnt
python3 -m http.server 18080 --bind 127.0.0.1
# 다른 터미널
curl -I http://127.0.0.1:18080
ss -lntp | grep ':18080'
# 같은 포트로 두 번째 서버를 띄우면 Address already in use
python3 -m http.server 18080 --bind 127.0.0.1
```

## 문제 해결
연결 거부는 서버 실행 여부와 포트를 먼저 확인한다. 이름 해석 오류는 DNS를 확인한다. HTTP 404는 접속에는 성공했지만 요청 경로가 없다는 뜻이다. 포트 충돌은 기존 프로세스를 확인하거나 다른 포트를 선택해서 해결한다. 실습 종료 시 첫 터미널에서 Ctrl+C로 종료한다.

## Docker와의 연결
`8080:80`은 호스트 8080을 nginx 컨테이너의 80에 연결한다. web 3개가 같은 호스트 포트를 각각 쓰면 충돌하므로 web에는 `expose: 5000`만 두고 nginx만 8080을 공개했다. Redis는 서비스 이름 `redis`로 접근하고 호스트 포트를 공개하지 않았다.
